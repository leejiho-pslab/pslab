# 발행 · 스케줄링 (무인 안전장치)

목적: 예약 발행 로직(`publish-plan`), 일일 배치(`schedule-daily`), DRY_RUN 안전장치·멱등성, 조용한 실패를 막는 무인 안전장치 3종의 단일 출처.

---

## 예약 발행 — `publish-plan --due`

`scheduledFor <= now` 이고 status가 published/manual이 아닌 항목을 발행한다.
- 자동채널(인스타·스레드·블로거·링크드인·유튜브)은 실제 게시, 수동채널(네이버 블로그)은
  status=`manual`로 표시(대시보드에서 복붙 → [06-대시보드.md](06-대시보드.md)).
- 유튜브 항목은 카드 이미지 없이 `videoFile`만 있어도 발행되며 `ytTitle`/`ytDescription`/`ytTags`
  (SEO 메타)를 우선 사용.
- `PSLAB_DRY_RUN=true`면 상태 변경 없이 시뮬레이션(가짜 '발행됨' 방지). 실제 발행 ON은
  `PSLAB_DRY_RUN=false`(온보딩 ⑦단계).
- **🚦 발행 전 검수 게이트**: `--due` 발행 전에 열려 있는 `[수정요청·채널]` 이슈를 조회해
  (`revision-gate.ts`), 걸린 콘텐츠는 ⛔ 보류하고 이슈가 닫힌(처리완료) 다음 사이클에 발행.
  `--id` 수동 발행은 게이트 미적용. 규약·흐름은 [06-대시보드.md](06-대시보드.md) §7.

## 일일 18시 배치 — `schedule-daily.mjs`

미발행 항목을 하루 1개씩 18:00 KST 재배치(채널 라운드로빈).
- cron `0 9 * * *`(09:00 UTC = 18:00 KST) + `30 9 * * *`(보정).
- **publish-plan은 멱등**이라 재실행해도 중복발행 없음.
- 필요시 `--perday`로 하루 배치 개수 조정(예: `--perday 2`).

## 무인 안전장치 3종 (조용한 실패 방지)

1. **발행 실패 즉시 푸시** — 성공뿐 아니라 채널별 실패도 텔레그램으로 알림(에러 메시지 포함).
   "발행이 며칠째 멈췄는데 아무도 몰랐다" 사태 차단.
2. **토큰 조기경보** — `check-tokens`가 인스타/스레드(라이브 핑+만료일) 외에 **유튜브·블로거
   (refresh token 실제 교환 시도)**, **링크드인(401 감지)**까지 매 사이클 점검. "새로 생긴" 경고만
   텔레그램 푸시(반복 스팸 방지), 대시보드 배너는 해결될 때까지 계속 표시.
3. **미설정 채널 구분** — 자격 증명이 아예 없는 채널(의도적 보류)은 조용히 대기시키고, 자격 증명이
   "있는데" 실패하면(토큰 만료 등) 사고로 취급해 알림. 보류 채널 때문에 매일 가짜 경고가 오는 스팸과,
   진짜 사고가 묻히는 것을 동시에 방지.

텔레그램 연결(`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`) 발급은 [04-채널연동.md](04-채널연동.md).
"발행이 며칠째 안 된다" 보고를 받았을 때의 점검 순서는 [08-함정과-결정.md](08-함정과-결정.md).
