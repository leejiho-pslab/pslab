# 도메인 · 데이터 계약

목적: 클라이언트 설정(`clients/<id>.json`)과 클라이언트 데이터(`data/clients/<id>/*`) 파일들의 역할·격리 규칙·강제 커밋 규칙을 정의하는 단일 출처.

이 시스템은 **멀티 클라이언트**다. 코드/스크립트/워크플로는 모두 공유하고, 업체별로 다른 것은
오직 **설정과 데이터**뿐이다. 그래서 업체를 하나 추가한다는 것은 곧 아래 설정/데이터 계약을
채우는 일이다. (코드 파일의 전체 지도는 각 개념 문서의 앵커로 분산돼 있다 — 여기서는 데이터/설정
계약에 집중한다.)

---

## 설정표 — `clients/<id>.json` (`ClientConfig`)

- `accounts`: 채널별 계정 핸들(표시용).
- `channelLinks`: 대시보드 "채널 바로가기" 카드용 채널별 관리/프로필 URL.
  없으면 채널별 기본 관리콘솔로 자동 폴백 — `src/core/dashboard.ts`의 `defaultManageUrl()` 참고.
- `reviewMode`: `normalizeClientConfig`가 요구하는 필수 필드 — **누락 금지**.
- 신규 업체 세팅 초기엔 `manualPlan:true`(검수 우선)로 둔다.
- 기존 `demo-cafe`/`pslab` 설정을 템플릿으로 복사해 값만 교체한다.

> 계정 핸들은 이 `accounts`가 **단일 출처**다(중복 정의 금지 → [../adr/0009-계정핸들-단일출처.md](../adr/0009-계정핸들-단일출처.md)).

## 클라이언트 데이터 — `data/clients/<id>/`

업체의 브랜드·콘텐츠·성과 데이터는 모두 이 폴더 아래에 격리된다.

| 파일 | 역할 |
|---|---|
| `plan.json` | 기획안(콘텐츠 항목·상태). 빈 골격은 `{items:[]}` |
| `design.json` | 팔레트 등 디자인 설정 + AI 메모 `notes` + **운영자 지시 `humanNotes`**(아래 ⚠) |
| `design-tokens.json` | **카드 렌더러 색·레이아웃 토큰 — 코드 수정 없이 디자인 조정**(SKILL §0 변수 #4) |
| `design-reference.json` | **드라이브(`※alway on/<n>. <업체>/`) 폴더 ID + 채널별 레퍼런스·지침 학습 결과**(SKILL §0 변수 #11) — 기획·제작 전 필수 열람 → [02-콘텐츠-엔진.md](02-콘텐츠-엔진.md) |
| `learning.json` | 자체학습 결과(다음 기획에 반영) |
| `bg-sources.json` | 힉스필드 배경 사진 URL |
| `video-sources.json` | 쇼츠 모션클립 URL(구형 단일클립 방식) |
| `reel-scenes.json` | **릴스 비트별 대본·장면 클립 URL**(현행 멀티씬 방식 → [02](02-콘텐츠-엔진.md)) |
| `blog-figures.json` | 블로그 본문 삽입 이미지 시드 |
| `keyword-trends.json` | 네이버 데이터랩/검색광고 실 검색관심도 — 대시보드 트렌드/키워드 표의 소스 |
| `brand-brief.json` | 운영자 지침 — 브랜드 노트(분석/방향성/감도) |
| `channel-guides.json` | 운영자 지침 — 채널별 주제 풀·핵심 가이드 |
| `weekly-reports.json` | 주간 리포트 |
| `token-health.json` | 토큰 만료 점검 결과 |

각 파일이 어떻게 생성/소비되는지는 콘텐츠([02-콘텐츠-엔진.md](02-콘텐츠-엔진.md))·기획([03-기획-지능.md](03-기획-지능.md))·
대시보드([06-대시보드.md](06-대시보드.md)) 문서 참고.

### ⚠ 사람 지시 우선 (`design.json` → `humanNotes`)

`design.json`에는 두 종류의 메모가 있고 **우선순위가 다르다**.

| 필드 | 누가 씀 | 규칙 |
|---|---|---|
| `notes` | AI(자체학습) | AI가 자유롭게 갱신 |
| **`humanNotes`** | **운영자(사람)** | **AI가 지우거나 덮어쓰지 못한다.** 프롬프트에서 **최우선**으로 반영 |

운영자는 대시보드 **🎨 디자인 피드백**(이슈 규약 `[디자인피드백]`, 본문 한 줄 = 지시 1건)으로 입력하고,
그 내용이 `humanNotes`에 누적된다 → [06-대시보드.md](06-대시보드.md).
**"AI가 사람 지시를 덮어써서 같은 피드백을 반복하게 되는 것"**이 이 규칙이 생긴 이유다.

## 멀티클라이언트 격리 원칙

- **업체별로 브랜드·콘텐츠·성과가 완전히 섞이지 않아야 한다.** 과거 다른 프로젝트가 같은
  repo/Pages를 공유해 배포 충돌이 난 사례가 있다(→ [07-인프라-배포.md](07-인프라-배포.md)의 배포 충돌 함정).
- 완전 분리를 원하면 업체별 전용 저장소/전용 링크로 분리한다(비개발자 온보딩 시의 실전 절차는
  [04-채널연동.md](04-채널연동.md)).

## `git add -f` 규칙 (필수)

**`data/clients/**`는 기본 gitignore 대상**이다. 그래서 시드 데이터 파일을 새로 추가하면 반드시
`git add -f`로 **강제 커밋**해야 한다.

- 안 하면 CI에서 렌더 스크립트가 입력 파일 없이 **0초만에 조용히 종료**되고, 그 결과 다운로드
  링크가 404("사용할 수 없는 파일")로 깨진다(예: `blog-figures.json`을 빠뜨린 경우).
- 새 시드 데이터 파일(`bg-sources.json`, `video-sources.json`, `blog-figures.json`,
  `keyword-trends.json` 등)을 추가하면 **항상 강제 커밋했는지 확인**할 것.
