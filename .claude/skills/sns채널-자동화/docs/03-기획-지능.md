## 키워드 기반 기획 시스템

### 가짜 트렌드 패널 금지 → 실 검색량 데이터
대시보드에 임의의 "가짜 트렌드 패널"을 만들지 않는다. 대신 실제 검색 데이터를 쓴다.
- 네이버 데이터랩(PlayMCP `datalab_search`)으로 상대 검색관심도를 받아 `keyword-trends.json`에 저장,
  `src/core/dashboard.ts`가 표로 렌더(네이버 불가 시 구글 트렌드 폴백).
- 검색량 낮은 키워드가 드러나면 소재 우선순위 조정에 활용.

### 키워드 기반 기획 시스템 (권장 · 상위호환)
상대지수(데이터랩)보다 **실제 월간검색수**가 기획에 더 정확하다.
- `scripts/fetch-keywords.mjs`가 **네이버 검색광고 API `/keywordstool`**(HMAC 서명)로 시드
  키워드의 월간검색수(PC/모바일)·경쟁정도 + 검색량 상위 연관키워드(발굴)를 받아 `keyword-trends.json`
  **v2**로 저장.
- 시크릿: `NAVER_AD_API_KEY`(액세스라이선스)·`NAVER_AD_SECRET`(비밀키)·`NAVER_AD_CUSTOMER_ID`
  (계정번호, 검색광고>도구>API 사용 관리에서 발급).
- 대시보드 blogSection이 v2(월간검색수·경쟁·발굴후보)/v1(상대지수) 자동 분기.
- 워크플로에 매 사이클 수집 스텝. **블로그 소재는 검색량 상위 키워드 우선으로 기획**한다.

### 3시트 구조 (v3)
`core`(핵심=브랜드 최상위 연관)·`related`(연관=파생 관련어)·`timely`(시의성=월별 시즌 캘린더 시드)
각 검색량 상위 20 + `baseDate`(기준일). 워크플로 **금요일 게이트**로 주1회 갱신(기준일 고정).
(→ [../adr/0005-네이버-키워드-3시트-기획.md](../adr/0005-네이버-키워드-3시트-기획.md).)

### 차주 주간 스케줄링
`scripts/plan-week.mjs`가 **토요일**에 상위 키워드로 다음주(월~일) 콘텐츠 기획안(채널·날짜·제안제목)을
`week-plan.json`에 생성 → 대시보드 "📅 차주 콘텐츠 기획" 패널. **plan.json은 미변경(안전)** — 실제
제작은 이 기획안 기준으로 감도·가짜글자 검수 후 진행. 시의성 키워드는 주 1회 배치.
(→ [../adr/0006-차주-주간-스케줄링.md](../adr/0006-차주-주간-스케줄링.md).)

## 레퍼런스·벤치마킹 수집 (경쟁·감도 인텔리전스)

경쟁·감도 레퍼런스 계정의 실제 게시물을 수집해 **기획·감도 참고**로 쓴다(내부용 — 남의 이미지 재게시 금지).

- **방식**: 인스타 Graph API **`business_discovery`** — 우리 **기존 발행 토큰을 재사용**
  (`PSLAB_INSTAGRAM_ACCESS_TOKEN`/`PSLAB_INSTAGRAM_IG_USER_ID`). 남의 계정 미디어를 여는 공개 API가
  달리 없어 이게 유일한 정식 경로다. **단, 대상이 "공개 비즈니스/크리에이터 계정"일 때만** 반환 —
  개인·비공개 계정은 에러 → **자동 스킵**.
- **설정**: `clients/<id>.json`의 `benchmarks.instagram: ["계정1","계정2",...]`(단일 출처).
- **스크립트**: `scripts/fetch-references.mjs` → 각 계정 최근 게시물(이미지·캡션·좋아요/댓글) 수집,
  이미지는 `docs/references/<id>/`로 **다운로드**(fbcdn URL이 몇 시간 뒤 만료되므로 로컬화) →
  `data/clients/<id>/references.json` 저장.
- **워크플로**: 월요일(+수동) 수집 스텝. 이미지는 `docs/`에 있어 github.io로 배포되므로 별도 CDN
  allowlist 불필요(우리 콘텐츠와 동일).
- ⚠ **스코프 함정**: `business_discovery`는 토큰에 **`instagram_basic`** 권한이 필요하다. 발행 권한
  (`instagram_content_publish`)만으론 부족할 수 있어 — **수집 0건이면 토큰 스코프부터 의심**하고
  Graph API 탐색기에서 `instagram_basic`을 추가해 재발급한다. 우리 조회 계정도 **비즈니스 계정 +
  페이스북 페이지 연결**이 돼 있어야 한다.
- **저작권/윤리**: 내부 벤치마킹·감도 참고 전용. 수집물을 우리 채널에 재게시하지 않는다.
- **상태**: 수집 엔진·설정·CI는 구현 완료. 대시보드 "🔍 레퍼런스·벤치마킹" 갤러리 패널은 **수집 실검증
  후 연결 예정**(아직 미구현 — 문서만 앞서지 않게 여기 명시).
  (→ [../adr/0011-레퍼런스-수집-business-discovery.md](../adr/0011-레퍼런스-수집-business-discovery.md).)

## 지침 시스템 (v3) — 운영자 입력 창구

AI가 "상시 학습"하는 운영자 입력 창구(`src/core/guidance.ts`).

- 대시보드 **🧭 지침 탭**: 브랜드 노트(분석/방향성/감도) 3종 + 채널별 주제·핵심 가이드 작성 폼.
  이슈 제목 규약 `[브랜드노트·분석|방향성|감도]`, `[가이드·<채널key>]`(본문 `주제:` 줄 = 우선 소재 풀).
  (대시보드 탭 UI 자체는 [06-대시보드.md](06-대시보드.md).)
- **guidance-sync.yml**(`on: issues`): 규약 이슈를 파싱해 `data/clients/<id>/brand-brief.json` +
  `channel-guides.json`에 반영 → 대시보드 재생성·커밋 → **이슈 자동 닫기(반영 완료 코멘트)** → Pages 배포.
  ※ issues 이벤트는 **기본 브랜치의 워크플로만** 실행되므로 반드시 기본 브랜치에 있어야 함.
- **생성 파이프라인 연동**: 오케스트레이터가 사이클마다 로드 —
  - 채널 가이드 topics → `reinforcement.favoredTopics` 선두 + research keywords 병합(소재 선정 우선),
  - 브랜드 노트(`brandNotesText`) + 가이드 본문 → `ContentBrief.brandNotes/channelGuide` →
    Claude systemPrompt에 "[운영자 브랜드 노트]" / "[채널 핵심 가이드]" 블록으로 주입.

채널별 전략을 지침에 반영하는 온보딩 흐름(④단계)은 [00-개요와-온보딩.md](00-개요와-온보딩.md) 참고.

## 자체 학습 선순환 (insight / learning)

발행 → 반응 수집(`collect-insights`, `src/core/insight.ts`) → `learning.json`(`src/core/learning.ts`)
→ 다음 기획에 디자인/주제/시간대 반영. 자체학습 반영은 `src/core/generate.ts`(기획 생성 + 학습 반영)에서
이뤄진다.

### ⛔ 성과 지표는 실측만 (가짜 지표 금지 — 사고 사례)

- **지표는 반드시 실측**한다(유튜브는 Data API v3 `statistics`).
  **가짜/의사(pseudo) 지표가 학습에 들어가면 안 된다.**
- 사고: 유튜브 플러그인이 한때 **해시 기반 의사 지표(수만 뷰)**를 반환해 **변형 학습이 통째로 오염**됐다
  (2026-07). 지표가 그럴듯해 보여서 오염을 늦게 발견한 것이 더 큰 문제였다.
- 규칙:
  - `fetchAnalytics`는 **dryRun에서만** 시뮬레이션값을 쓰고, 실발행은 **실제 API 값**만 쓴다.
  - 수집이 실패하면 **가짜로 채우지 말고 실패로 기록**되게 둔다(빈 값 > 거짓 값).
  - 디자인 변형(A/B/C)·모티프 비교는 **인스타 발행분 한정** — 채널별 지표 스케일이 섞이면 왜곡된다.
