# 대시보드 (관제실 · 지침 탭 · 안정성)

목적: 대시보드(`src/core/dashboard.ts`, GitHub Pages)의 구성·v2 업그레이드·지침 탭·레이아웃 원칙·채널 스코프·안정성 수칙의 단일 출처. "대시보드가 곧 제품이다".

---

## 구성 (`src/core/dashboard.ts`)

채널현황·발행/대기·성과·오픈 체크리스트·주간리포트·네이버/유튜브 도우미·**채널 바로가기**(개요 탭
상단, 채널별 파스텔 카드 → 클릭 시 관리/프로필로 이동. `channelLinksPanel()`). 5분 자동 새로고침.
**빈 화면 방지**: 메인 스크립트 앞 `window.onerror` + 렌더 try/catch로 오류를 화면에 표시.

수동 채널(네이버) 복붙/이미지 다운로드 도우미(`manualHelper`)의 본문 이미지 파싱은 [02-콘텐츠-엔진.md](02-콘텐츠-엔진.md).

## 대시보드 v2 업그레이드 (라이트 테마 + 기간 + 수정요청 게시판)

1. **라이트 테마** — 배경 화이트/폰트 블랙(`:root{color-scheme:light}`). 배지·그라데이션·인라인
   색상까지 전부 라이트 팔레트. 다크로 되돌리려면 `<style>` 블록과 JS 인라인 색상을 함께 바꿔야 함.
2. **운영 기간 선택** — 전역 상태 `period` + `periodBar()`(전체/최근7·14·30일/이번달/지난달/직접선택
   date input). `inPeriod(date)`로 개요·채널 상세의 KPI·추세·발행 데이터·발행됨 카드가 모두 필터됨.
3. **메인(전체 탭)은 발행 전 콘텐츠만** — 기획안 그리드는 `status!=='published'`만. 발행분은
   "발행된 게시물 · <기간>" 섹션에서 기간 필터로 조회(기획 발행분 planCards + 사이클 발행분 병합).
4. **채널 상세도 기간 반영** — KPI는 사이클 발행분(published)+기획 발행분(planPub)을 **합산**(mAll).
   발행 대기 목록은 발행 전만, 발행됨 목록은 기간 필터.
5. **수정요청 게시판**(`requestsPanel()`) — 각 채널 탭 최상단. **📅 대상 콘텐츠 셀렉트**(그 채널
   기획 콘텐츠를 발행일·제목으로 특정, 기본 '채널 공통') + **🏷 수정 항목 셀렉트**(`REQ_TYPES`:
   텍스트/이미지/영상/디자인/해시태그·키워드/발행 일정/기타) + textarea → 제목 규약
   `[수정요청·<채널key>] [<항목>] 첫줄`, 본문에 `대상 콘텐츠:`(plan id 포함)·`수정 항목:` 줄.
   깃허브 이슈 생성(라벨 feedback), 백엔드 없이 동작 — 처리자는 본문 plan id로 대상 기획을 특정한다.
6. **처리 상태 자동 표시** — `loadIssues()`가 GitHub API(공개 repo, 무인증)로 이슈를 읽어 제목 규약을
   파싱: open=🛠 처리중, closed=✅ 처리완료. 채널 탭 메뉴에 `treq` 배지(🛠n/✅), 채널별 요약 표에
   수정요청 열. **운영자는 이슈를 닫는 것으로 '처리완료' 처리**.

## 지침 탭 (대시보드 쪽 UI)

- 대시보드 **🧭 지침 탭**: 브랜드 노트(분석/방향성/감도) 3종 + **🎨 디자인 피드백** + 채널별
  주제·핵심 가이드 작성 폼.
  (이슈 제목 규약·guidance-sync 워크플로·생성 파이프라인 연동 등 지침 시스템의 동작은
  [03-기획-지능.md](03-기획-지능.md).)
- **이슈 제목 규약**: `[브랜드노트·분석|방향성|감도]` · **`[디자인피드백]`** · `[가이드·<채널key>]`
  · **`[레퍼런스·<채널key>]`**(본문 한 줄 = 링크 1개, 링크 뒤 메모 가능 → `reference-links.json`
  pending 적재, 학습은 세션 게이트 → [02-콘텐츠-엔진.md](02-콘텐츠-엔진.md) 레퍼런스 링크 인박스)
  (본문 `주제:` 줄 = 우선 소재 풀).
  반영 대상 → `brand-brief.json` · `channel-guides.json` · **`design.json` `humanNotes`**
  (`[디자인피드백]` — **본문 한 줄 = 지시 1건**, 사람 지시는 AI가 못 지움 → [01-도메인-데이터.md](01-도메인-데이터.md)).
  처리 흐름: 이슈 → 데이터 반영 → 대시보드 재생성·커밋 → **이슈 자동 닫기(반영 완료 코멘트)** → Pages 배포.
- **채널 가이드는 지침 탭 전용**(운영자 지시로 채널 탭 요약 패널 폐지) — 채널 탭 같은 자리에는
  **📊 콘텐츠 리포트**(`contentReportPanel`): 발행/대기/평균 참여율/누적 조회·좋아요 KPI +
  반응도 추세 + 콘텐츠별 실측 성과 표(조회·좋아요·댓글·참여율·인사이트·발행 링크), 기간 필터 연동.
  성과는 실측만 표시(허수 금지).
- **지침 탭 실시간 반영**: `loadIssues()`가 지침 이슈(`[브랜드노트·…]`·`[디자인피드백]`·
  `[가이드·<채널>]`)를 직독해, 데이터 반영 전에도 해당 항목 위에 **"🕓 접수됨 — 반영 처리중"
  미리보기**를 띄운다(레퍼런스 인박스와 동일한 즉시 반영 패턴).
- 각 채널 탭에 **🔗 레퍼런스 링크 패널**(`referencePanel`) — 등록 폼 + 해당 채널 링크의
  상태(학습대기/학습완료/열람실패)·학습 요약. 지침 탭에는 전 채널 학습 현황 표 — 운영자가
  "무엇을 배웠고 어디에 반영했는지"를 검수하는 화면이다.

## 대시보드 개요 레이아웃 원칙

중요도 순 — ①채널 바로가기 → ②📅 차주 콘텐츠 기획 → ③성과/발행 → (**최하단**) 🔌 채널 연결 상황
(압축 칩: 채널별 ✅/⬜ 만). 오픈 준비 체크리스트 같은 저중요 패널은 최하단으로.

## 헤더 로고 · 타이틀

제품 브랜드 **"ALWAYS ON 콘텐츠 관제실"** 고정(`src/core/dashboard.ts`의 `<title>`+`.brand`). 업체
식별은 헤더 클라이언트 칩(`accounts`/client name)으로 표시되니 로고엔 업체명 대신 제품명을 쓴다.

## 채널 스코프 (`CHANNELS`)

대시보드 채널 목록은 `src/core/dashboard.ts`의 `CHANNELS` 상수. 업체가 안 쓰는 채널(예: 링크드인)은
**`CHANNELS`에서 제거**하면 네비·바로가기·연결상황·캡션라벨 등에서 전부 사라진다(잔여 `linkedin`
흔적 문자열도 같이 정리). (→ [../adr/0008-채널-스코프-미사용채널-제거.md](../adr/0008-채널-스코프-미사용채널-제거.md).)

## 안정성 수칙

- 모든 외부 API 호출은 `timedFetch`(기본 60초, 유튜브 업로드 600초) 사용 — 응답 없는 연결이 크론
  잡을 몇십 분씩 묶어두는 사고 방지(2026-07-09 15분 행 사례). 워크플로 잡에는 `timeout-minutes`
  (cron 25분/publish 15분/sync 15분) 필수.
- **인라인 JS onclick 이스케이프**: 대시보드 인라인 JS의 onclick 문자열은 TS 소스에서 `\\'`(백슬래시
  2개)로 이스케이프해야 함 — `\'` 하나면 SyntaxError로 대시보드 전체가 오류 화면이 된다.
- **정규식도 같은 함정**: 클라이언트 스크립트(plainHead 등)는 TS 템플릿리터럴로 emit되므로,
  브라우저에서 `*`를 지우려면 소스에 `/\\*/g`(백슬래시 2개)라고 써야 한다(→ 브라우저에 `/\*/g`로
  풀림). 소스에 `/\*/g`로 쓰면 브라우저엔 `/*/g`가 되어 "Invalid regular expression: missing /"로
  화면이 깨진다.
- **`vm.Script` 검증 필수**: 대시보드 로직을 고치면 반드시 로컬에서 `dashboard --out`으로 생성 후
  인라인 `<script>`를 `vm.Script`로 파싱 검증하고 배포할 것(브라우저에서만 터지는 오류를 CI가 못 잡는다).
  (→ [../adr/0007-대시보드-템플릿리터럴-이스케이프.md](../adr/0007-대시보드-템플릿리터럴-이스케이프.md).)
