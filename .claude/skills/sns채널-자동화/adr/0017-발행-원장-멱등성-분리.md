# ADR-0017: 발행 멱등성을 plan.json 상태에서 분리 — append-only 발행 원장

- **상태**: 채택됨
- **날짜**: 2026-08-03
- **관련 SKILL**: §5
- **관련 ADR**: —

## 맥락 (Context)

2026-07-31 발행분이 **인스타그램·유튜브에 각각 2개씩 중복 게시**됐다. 운영자가 직접 지웠다.

원인 추적:

| 시각 | 사건 | `reels-07-31.status` |
|---|---|---|
| 07-31 20:42 | CI 가 발행 성공, 커밋 | `published` |
| 08-01 01:19 | 세션이 **오래된 로컬 plan.json 을 그대로 커밋** | **`planned`** ← 롤백 |
| 이후 | 크론이 "예정시각 지났는데 planned" 로 판단 | **재발행** |

기존 멱등성은 `publish-plan` 의 필터 한 줄에 전부 걸려 있었다.

```ts
if (it.status === 'published') return false;
```

그런데 `plan.json` 은 기획·상태·산출물이 한 파일에 뒤섞여 있고 **사람과 CI 가 함께 고친다.**
병합 충돌 해소, 오래된 체크아웃 커밋, 수동 편집 — 상태가 되돌아갈 경로가 여럿이다.
되돌아가는 순간 그 항목은 "아직 안 나간 것"이 되어 다시 나간다.

즉 **되돌아갈 수 있는 파일에 "이미 내보냈다"는 사실을 맡긴 게** 설계 결함이었다.
운영 실수는 방아쇠였을 뿐, 같은 사고는 어떤 경로로든 다시 난다.

## 결정 (Decision)

**"이미 내보냈다"는 사실만 append-only 원장으로 분리한다.**

`data/clients/<id>/published-ledger.json` — `itemId → { firstPublishedAt, channels, refs[] }`

1. **발행 전 검사**: 원장에 있으면 `status` 와 무관하게 건너뛴다.
2. **발행 직후 기록**: 성공하면 원장에 append 하고 **즉시 저장**한다.
   (`plan.json` 저장은 루프 끝 한 번뿐이라, 거기에만 기대면 중간에 죽었을 때 다음 사이클이 재발행한다)
3. **자가 복구**: 원장에는 있는데 `plan` 이 미발행이면 상태를 되돌려 놓고 경고한다.
   이걸 안 하면 대시보드가 "발행 대기"로 잘못 보이고 **사람이 수동 발행해 또 중복이 난다.**
   발행할 항목이 없어도 복구분은 저장한다(early `continue` 로 유실되던 것).
4. **지우지 않는다**: 재발행이 필요하면 운영자가 원장에서 해당 키를 명시적으로 지운다.

## 고려한 대안 (Options)

- **A안(채택) — 별도 append-only 원장**
  `plan.json` 이 어떤 이유로 되돌아가도 사실은 남는다. 병합 충돌이 나도 **합집합이 정답**이라
  해소가 안전하다. 자가 복구까지 붙여 대시보드 표시도 함께 맞춘다.
- **B안 — `plan.json` 에 `publishedAt` 유무로 판단**
  파일이 하나라 간단하지만 **같은 파일이 통째로 되돌아가면 같이 사라진다.** 사고를 못 막는다.
- **C안 — 발행 전 채널 API 로 중복 조회**
  가장 정확하지만 채널마다 조회 방식이 다르고 rate limit 이 있으며, 캡션이 같은 다른 게시물과
  구분이 어렵다. 매 발행마다 왕복이 늘어 크론이 느려진다.
- **D안 — 사람이 조심한다(운영 규칙만 추가)**
  이번에도 규칙은 있었다. 자동화가 매일 도는 이상 사람 주의력에 기대면 안 된다.

## 결과 (Consequences)

- (+) `plan.json` 이 되돌아가도 중복 발행이 안 난다. 롤백·병합사고·수동편집 전부 방어.
- (+) 상태가 어긋나면 **자동으로 맞춰지고 경고가 뜬다** — 조용히 틀어져 있지 않는다.
- (+) 원장에 `remoteId` 가 남아 중복분을 찾아 지울 때 쓸 수 있다.
- (−) 파일이 하나 늘고 `git add -f` 대상이 하나 더 생긴다(`data/` 는 gitignore).
- (−) **의도적 재발행이 한 단계 번거로워진다** — 원장에서 키를 지워야 한다. 사고 방지의 대가로 수용.
- (−) 원장이 유실되면 방어가 사라진다. 그래서 파싱 실패 시 **크게 경고하고** 빈 원장으로 진행한다
  (발행을 멈추면 운영이 서므로, 막지는 않는다).
