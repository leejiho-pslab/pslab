# ADR-0013: 분화된 스킬 단일화 + 클라이언트 변수화

- **상태**: 채택됨
- **날짜**: 2026-07-30
- **관련 SKILL**: `sns채널-자동화` (§0 클라이언트 변수 계약, §0-1 배포 모드)
- **관련 ADR**: [0010 병렬브랜치 통합정책](0010-병렬브랜치-통합정책.md) · [0012 문서체계 재편](0012-문서체계-재편-역이식-동기화.md)

## 맥락 (Context)

같은 `sns채널-자동화` 스킬 **하나**가 브랜치별로 두 갈래로 분화해 각자 발전했다(조사 결과).

| 계열 | 브랜치 | 마지막 스킬 커밋 | 규모 | 성격 |
|---|---|---|---|---|
| **A** | `main` / `eager-lamport` | 07-30 04:11 | 1파일 24,327 B | 모놀리식. 실전 교훈 6종 보유 |
| **B** | `brand-research` / `vittz-prep` / `guide` | 07-18 01:16 | 25파일 97,644 B | 허브+docs+ADR 도서관형. 7단계 게이트 보유 |
| C | `eager-mayer` / `keek` / `remotion` / `skill-installation` | 07-10 / 07-07 | 1파일 21,316 B | 분화 이전 사본(고유 변화 없음) |

- 분화 기점: `1a885bbf` (07-16 20:24, 당시 1파일 21,316 B).
- **시간 최신(A)과 내용 최신(B)이 서로 다른 브랜치**였다 → 한쪽만 택하면 확정 유실.
  - A만 택하면: 7단계 검수 게이트 + docs 9권 + ADR 14권 유실.
  - B만 택하면: 릴스 멀티씬(무음 원칙)·실측 지표 원칙·design-tokens·humanNotes·site-view·
    환경 네트워크 정책 유실.
- 추가로 운영자 요구: **스킬은 특정 업체에 고정되면 안 되고, 업체 차이는 변수로 표현**되어야 한다.
  (조사 시 A는 `pslab` 18회, B는 `동성`/`awk` 언급이 있었으나 모두 네임스페이스·검증출처·예시였고
  하드코딩은 아니었다. 다만 **규칙으로 못 박아 두지 않으면 재발**한다.)

## 결정 (Decision)

1. **B의 도서관 구조(허브 + `docs/` + `adr/`)를 틀로 채택**하고, **A의 고유 내용 전부를 해당 `docs/`로
   이식**한다. 즉 **합집합**이며, 어느 쪽도 버리지 않는다.
2. `SKILL.md`에 **§0 클라이언트 변수 계약**을 신설한다 — 업체마다 달라지는 것을 **변수 10개**로 고정하고,
   "업체명 하드코딩 금지 / 코드 분기 금지, 갈라질 것 같으면 변수로 승격"을 규칙으로 명시한다.
3. **배포 위치도 변수로 만든다** — `deployMode = shared | dedicated`.
   "pslab 저장소 안에 넣을까 / 업체별 전용 저장소로 분리할까"를 **정책 논쟁이 아니라 업체별 설정**으로
   전환한다. 업체 2곳 이상이면 `dedicated` 권장.
4. C계열(분화 이전 사본)은 스킬 관점에서 고유 변화가 0이므로 **스킬 파일은 버려도 무손실**이다
   (각 브랜치의 다른 자산은 별개로 판단).

## 고려한 대안 (Options)

- **A안(채택) — 합집합 + 변수화**: 유실 0. 문서량이 커져도 개념별 분권이라 관리 가능.
- **B안 — main 모놀리식 유지 + 게이트만 흡수**: 간단하지만 ADR 14권·docs 9권 유실. 기각.
- **C안 — 스킬 2개로 병존**: 다음 세션이 어느 것을 정본으로 볼지 몰라 혼란. 기각.
- **D안 — 배포 방식을 하나로 강제**: 업체 상황(수·독립성)에 따라 최적이 달라 부적합.
  → 변수(`deployMode`)로 전환해 해결.

## 결과 (Consequences)

- (+) 스킬이 **하나의 정본**으로 수렴하고, 시간·내용 최신이 한곳에 모인다.
- (+) 신규 업체 온보딩이 **"변수 10개 채우기"**로 축소된다(코드 무수정).
- (+) 저장소 배치 논쟁이 설정값으로 바뀌어, 업체 증가 시 파편화가 구조적으로 예방된다.
- (−) 문서가 25파일이라 **정본 위치(단일 출처)를 지키는 규율**이 필요하다 → 같은 내용을 두 곳에 쓰지 말고
  링크로 참조한다(ADR-0012 원칙 유지).
- (−) `deployMode`는 **문서상 계약**으로 먼저 도입됐다. `ClientConfig` 타입/코드 반영은 후속 작업이며,
  그때까지는 온보딩 시 수동으로 모드를 정해 적용한다.
