# ADR-0010: 병렬 브랜치 작업 통합(리베이스) 정책

- **상태**: 채택됨
- **날짜**: 2026-07-16
- **관련 SKILL**: —
- **관련 ADR**: —

## 맥락 (Context)
같은 `sns채널-자동화` 스킬을 서로 다른 브랜치에서 병렬로 수정한 상황이 생겼다(현재 작업선 vs
종료된 `claude/eager-mayer-tknneh` — AWK 클라이언트 + 신규 스킬 + 스킬 패키징). 방치하면 두
브랜치가 각각 병합되며 스킬 내용이 어긋나거나 한쪽 작업이 유실될 위험이 있었다.

## 결정 (Decision)
종료된 병렬 브랜치는 **현재 작업선으로 통합**해 단일 작업선을 유지한다. 절차:
1. 두 브랜치가 **동시에 건드린 파일(충돌 후보)**을 먼저 집계.
2. 충돌 후보가 없으면(0개) 현재 브랜치가 이미 푸시돼 있어도 **강제푸시 대신** 상대 커밋들을
   현재 HEAD 위에 **cherry-pick/rebase로 replay**(기존 해시 보존, 안전).
3. 스냅샷 산출물(스킬 패키지 zip 등)은 시점 스냅샷이라 **최신성만 확인**하고 필요시 재패키징.

## 고려한 대안 (Options)
- **A안(채택) — 충돌 점검 후 replay 통합**: 유실 방지 + 이력 보존, 강제푸시 회피.
- **B안 — 각 브랜치 개별 병합(merge)**: 간단. 단점: 분기 방치 시 스킬 내용 어긋남.
- **C안 — 병렬 브랜치 폐기**: 정리 쉬움. 단점: 그쪽 작업(AWK·신규 스킬) 유실.

## 결과 (Consequences)
- (+) 작업선이 하나로 모여 스킬 내용 어긋남·유실을 막는다.
- (−) 통합 시 스냅샷 산출물의 최신성을 별도로 확인해야 한다(옛 스킬 zip 등).
