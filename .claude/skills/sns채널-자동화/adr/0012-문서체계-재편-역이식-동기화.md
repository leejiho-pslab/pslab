# ADR-0012: 2계층 문서 체계 + 레퍼런스 동기화(역이식)로 파편화 제거

- **상태**: 채택됨
- **날짜**: 2026-07-16
- **관련 SKILL**: CLAUDE.md · SKILL.md · docs/* 전체
- **관련 ADR**: ADR-0000(ADR 도입), ADR-0009(핸들 단일출처), ADR-0010(브랜치 통합)

## 맥락 (Context)
스킬 지식이 긴 단일 `SKILL.md`(486줄)에 뭉쳐 있고, "왜"가 함정 목록에 섞여 추적이 어려웠다. 더 큰
문제로 **레퍼런스 구현(pslab)이 자기 문서가 설명하는 엔진 최신본을 안 가지고 있었다** — 이번 세션의
개선(render-ig·fetch-keywords·plan-week·ig-outro·대시보드 키워드3시트/차주기획)이 클라이언트
저장소(dongsung)에서만 이뤄져, SKILL이 설명하는 파일이 pslab엔 없는 **실구현↔문서 파편화**가 있었다.
운영자의 최상위 원칙: **"실구현과 문서상의 파편화 금지"**, **"에이전트 md는 인덱스를 참조하고,
참조 문서는 필요할 때 읽히며, 실수정 시 함께 갱신"**.

## 결정 (Decision)
1. **2계층 + 라우터 구조**: 자동 로드되는 **`CLAUDE.md`(+`AGENTS.md` 포인터)** 는 정체성·작업 규약·
   **개념 인덱스(문서 지도)**만 담는다. `SKILL.md`도 트리거+표준순서 요약만 남긴 **라우터**로 슬림화.
   상세 how는 개념별 **`docs/NN-*.md`**(단일 출처), 왜는 **`adr/`**. 서로 **링크로만** 참조(복제 금지).
2. **개념화 인덱싱**: 문서를 스킬 §절이 아니라 **개념(C1~C10)** 으로 재구성 — 특정 구현에 락인되지 않게.
3. **레퍼런스 동기화(역이식)**: 클라이언트에서 앞서간 **범용 엔진**을 pslab 레퍼런스로 되돌려 "문서=실제
   pslab 구현"을 일치시킨다. 클라이언트 특화(콘텐츠 시드·브랜드 값)는 제외. 다중 클라이언트 일반성은
   유지(예: 특정 업체가 안 쓰는 채널이라도 레퍼런스에선 보존).
4. **동기화 규약**: 코드가 바뀌면 매핑된 문서를 **같은 커밋**에서 갱신. 클라이언트에서 범용 엔진을
   고치면 레퍼런스와 동기화.

## 고려한 대안 (Options)
- **A안(채택) — 2계층 재편 + 역이식**: 파편화 근본 제거, 필요할 때만 읽는 인덱스로 자동로드 부담↓.
  단점: 초기 분해·역이식 작업량, 인덱스 최신화 규율.
- **B안 — SKILL.md 한 파일 유지**: 변경 최소. 단점: 비대·중복·"왜" 추적 불가, 자동로드 무거움.
- **C안 — 문서에 "pslab은 구버전" 명시만**: 빠름. 단점: 파편화 잔존 → 원칙 위배(기각).

## 결과 (Consequences)
- (+) 한 사실이 한 곳에만 있고 실제 파일에 앵커돼, 세션이 바뀌어도 문서가 거짓이 안 된다.
- (+) 자동 로드 문서가 가벼워지고, 개념 인덱스로 필요한 것만 읽는다.
- (−) 클라이언트별 저장소로 엔진이 복제되는 구조라, 범용 엔진 변경 시 **역이식 동기화 규율**을 계속 지켜야 한다.
- (−) 인덱스(CLAUDE.md 표)와 실제 docs가 어긋나지 않게 **추가·변경 시 표도 함께** 갱신해야 한다.
