# 다음 단계 진행 가이드 (NEXT-STEPS)

> 현재 상태: 4대 대시보드 + 자동화 골격 + 단일 서비스(도커) **완성**. 데이터는 mock 기본,
> 카페24만 주문 기반 live 가능. 아래는 "완성된 골격"을 **실제 운영 제품**으로 끌어올리는 순차 가이드.

남은 작업(실연동 / 디자인 디테일 / 탭 일관화 / 운영배포)은 서로 얽혀 있어 **4단계로 순서화**한다.
순서 원칙: ① 외부 의존 없는 것 먼저 → ② 자격증명 필요한 실연동 → ③ 운영 인프라 → ④ 고도화.

## STAGE 2 — 실 데이터 연동 (live) · 소스별 순차

각 collector 의 `collect_live` 를 실제 API/수집으로 채운다. mock 은 fallback 으로 유지.
**소스별로 독립**이라 가치/난이도 순으로 하나씩. 각 단계마다 `smoke_live` 로 검증.

| # | 소스 | 작업 | 상태 | 필요한 것(선행조건) |
|---|------|------|------|--------------------|
| 2-1 | **카페24 확장** | 방문자/회원/카테고리/베스트/디바이스/신규·재구매 매핑 | ⏳ | 카페24 앱 권한(scope) 확대 |
| 2-2 | **광고 — Meta** | Insights 클라이언트 + 매핑(단위검증) | ✅ 커넥터 | META_ACCESS_TOKEN·계정 ID |
| 2-3 | **광고 — Google** | searchStream(GAQL) 클라이언트 + 매핑(단위검증) | ✅ 커넥터 | dev token·OAuth·CID |
| 2-4 | **광고 — Naver/Kakao** | 네이버 GFA/SA, 카카오모먼트 리포트 | ⏳ | 각 플랫폼 API 키·문서 |
| 2-5 | **광고 소재** | DA 소재별 리포트 + 소재 이미지 URL | ⏳ | 위 광고 API 권한 |
| 2-6 | **경쟁사 — 네이버** | DataLab 검색 트렌드 클라이언트 + 매핑(단위검증) | ✅ 커넥터 | NAVER_CLIENT_ID/SECRET |
| 2-7 | **경쟁사 — 광고/베스트** | 메타·구글 광고 라이브러리, 베스트·후기 크롤링 | ⏳ | 수집 정책/대상 확정 |

- ✅ **커넥터** = 클라이언트 + 매핑 구현 + mock-transport 단위검증 완료. **자격증명만 넣으면 동작**
  (단, HTTP 엔드포인트/버전은 실 키로 1회 검증 권장 — 매핑 로직은 검증됨).
- **공통 패턴**: `collect_live` 구현 → `smoke_live --check` → 1일 수집 → 대시보드 확인 → 스케줄 편입
- **원칙**: 키 없는 소스는 자동 스킵 → **부분 롤아웃** 가능
- **결정/제공 필요**: 각 플랫폼 자격증명, Naver SA·Kakao API 문서, 경쟁사 수집 방식(API vs 크롤링)·대상

## 권장 진행 순서 요약

```
STAGE 1 (UI 확정·디테일)  ──▶  STAGE 2 (소스별 live, 2-1부터)  ──▶  STAGE 3 (운영배포)  ──▶  STAGE 4
        지금 바로                자격증명 확보되는 대로 순차            live 가동 후              선택
```

- **STAGE 1 은 지금 즉시** 착수 가능(외부 의존 0) → 화면을 못 박는다.
- **STAGE 2 는 자격증명이 곧 병목** → 확보된 소스부터 부분 롤아웃(스킵 구조라 안전).
- **STAGE 3 은 live 데이터가 생긴 뒤** 의미. 배포/스케줄/알림.
- 각 단계는 독립 PR로 쪼개 진행, 단계마다 테스트+스크린샷 검증.
