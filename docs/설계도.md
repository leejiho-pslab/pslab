# pslab SNS 자동화 솔루션 — 설계도

> 이 문서는 전문 용어 없이, **비유**로 전체 구조를 설명합니다.
> 목표: **사람이 거의 손대지 않고(95%→100%) 알아서 돌아가는 SNS 콘텐츠 공장**을 만들어
> 여러 클라이언트에게 **공장 한 대씩 복제해 납품**하는 것.

---

## 0. 한 장 요약

- **무엇**: 주제만 정하면 글·이미지·영상을 알아서 만들고, 여러 SNS에 알아서 올리고, 성적표까지 알아서 보내주는 자동 시스템.
- **대상 SNS**: 유튜브 · 네이버 블로그 · 인스타그램 · 스레드 · 링크드인
- **핵심 가치**: 사람의 일을 **"매일 글쓰고 올리기" → "가끔 OK만 누르기" → "아예 안 보기(100%)"** 로 줄인다.
- **사업 모델**: 공장을 잘 만든 뒤 **클라이언트마다 설정표 한 장**만 갈아 끼워 빠르게 납품.

---

## 1. 큰 그림 — 끝이 처음으로 이어지는 자동 컨베이어 벨트 🏭

원료(소재)가 들어가면 벨트를 타고 흘러가 완성품(게시물)이 나오고,
배달까지 끝나면 성적표가 다시 맨 앞으로 돌아와 **"다음엔 뭘 만들지"** 를 알려줍니다.
그래서 **쓰면 쓸수록 똑똑해지는** 둥근 벨트입니다.

```
        ┌──────────── 다시 처음으로 (AI 회의 → 방향 강화) ───────────────┐
        │                                                                │
        ▼                                                                │
  ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
  │ 1.소재   │ → │ 2.제작   │ → │ 3.검수   │ → │ 4.발송   │ → │ 5.성적표 │
  │ +시장조사│   │  (글/   │   │ (사람5%, │   │ (여러SNS │   │ +경쟁사  │
  │ +경쟁사  │   │ 그림/   │   │  나중엔  │   │  동시)   │   │  비교    │
  │  모니터링│   │ 영상,   │   │  끔)     │   │          │   │          │
  │          │   │ 장비자가│   │          │   │          │   │          │
  │          │   │ 업그레이드│ │          │   │          │   │          │
  └──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
     자동           자동          반자동→자동      자동      자동→AI회의실(6)
```

> 🔁 6번 **학습실(AI 회의실)** 은 위 그림 맨 위의 "다시 처음으로" 화살표에 해당합니다.
> 성적표를 받아 AI들끼리 회의 → 그 결론으로 1·2번을 더 똑똑하게 만든다.

## 2. 6개 작업소 상세 (각 단계가 무슨 일을 하나)

### 1️⃣ 소재 수집소 (= 시장 조사실) — "경쟁사 보면서 오늘 뭐 올릴지 알아서 정함"
- **하는 일**: 요즘 뜨는 키워드·뉴스·트렌드를 자동으로 긁어와 후보 소재를 만든다.
- **시장 조사 / 벤치마킹**: 클라이언트의 **경쟁사 계정과 "잘나가는 모범 콘텐츠"를 정찰 대상으로 등록**해 두고 24시간 감시한다. 경쟁사가 뭘 올려서 반응이 터졌는지, 요즘 이 시장에서 어떤 형식(릴스·카드뉴스·롱폼 등)이 먹히는지 계속 베껴 배운다(벤치마킹).
- **반응 따라 강화**: 우리 글이 올라가면 **반응 좋은 쪽(주제·형식·톤)을 기억해, 다음 소재를 그 방향으로 더 밀어준다.** → 쓸수록 "터지는 콘텐츠" 비율이 올라가는 구조.
- **재료**: 클라이언트의 업종/관심 주제 + **경쟁사·벤치마킹 대상 목록** (설정표에 적힌 것)
- **결과**: "오늘의 소재 후보" 목록 (경쟁사 동향 + 과거 반응이 반영된)
- **사람 개입**: 없음 (자동)

> 🔍 비유: 매일 아침 **경쟁사 매장을 둘러보고 오는 시장조사 직원**이 상주하는 셈. "옆집은 이걸로 줄 섰더라" → 우리도 그 방향으로 강화.

### 2️⃣ 콘텐츠 제작 공장 — "글·그림·영상을 찍어내고, 장비도 스스로 업그레이드"
- **하는 일**: 소재로 글을 쓰고, 어울리는 이미지·썸네일·(필요시)영상을 만들고, 해시태그를 달고, **클라이언트 말투에 맞춰** 다듬는다.
- **스스로 장비 강화 (자가 업그레이드)**: 공장이 멈춰 있지 않는다. **AI가 더 좋은 디자인·영상 도구(새 스킬·플러그인·MCP)를 스스로 찾아 들여오고 붙여서**, 제작 품질을 계속 끌어올린다. (예: 새 썸네일 생성 도구가 나오면 알아서 후보로 시험 → 결과 좋으면 정식 채택)
- **반응 반영**: 1번 소재실의 "반응 좋았던 형식·디자인"을 받아, 잘 먹히는 스타일로 제작을 기울인다.
- **재료**: 소재 + 클라이언트 브랜드 말투/금지어 (설정표) + 사용 가능한 제작 도구 목록
- **결과**: 바로 올릴 수 있는 완성 게시물
- **사람 개입**: 없음 (자동)

> 🛠️ 비유: 공장이 **스스로 새 기계를 사 와서 라인에 붙이는** 셈. 사람이 "이 도구 써라" 안 해도, 더 좋은 장비를 알아서 찾아 능력을 키운다.

### 3️⃣ 품질 검사대 — **여기가 그 '5%'** 👀
- **하는 일**: 올리기 직전 사람이 한 번 슥 보고 OK.
- **중요**: 이 단계는 **스위치**다. 켜면 사람이 보고(안전), **끄면 통과(100% 자동).**
- **계획**: 초기엔 켜서 신뢰를 쌓고, 안정되면 **클라이언트별로 하나씩 꺼서 완전 자동**으로 전환.
- **사람 개입**: 처음엔 OK 한 번 → 이후 0

### 4️⃣ 발송 센터 — "여러 SNS에 동시 배달"
- **하는 일**: 반응 좋은 시간대에 맞춰 5개 SNS에 한꺼번에 자동 게시.
- **재료**: 완성 게시물 + 클라이언트 계정 출입증 + 발송 시간표
- **결과**: 각 SNS에 게시 완료 + 게시 주소
- **사람 개입**: 없음 (자동)

### 5️⃣ 성적표실 — "결과를 알아서 정리해 보고"
- **하는 일**: 조회수·좋아요·댓글을 모아 표로 만들고, **클라이언트에게 자동 발송**(메일/메신저).
- **재료**: 게시 주소들 + 경쟁사 같은 기간 성적
- **결과**: 주간/월간 성적표 (우리 성적 **+ 경쟁사 대비** 비교 포함)
- **사람 개입**: 없음 (자동)

### 6️⃣ 학습실 (= AI 작전회의실) — "데이터만 적는 게 아니라, AI들이 모여 회의해서 방향을 바꾼다" (벨트가 1번으로 복귀)
- **단순 기록을 넘어선다**: 숫자를 표에 적고 끝내지 않는다. 서로 다른 역할의 **AI 여러 명이 한 테이블에 모여 토론**한다.
  - *분석 담당 AI*: "이번 주 반응 좋은 건 짧은 영상, 나쁜 건 긴 글"
  - *경쟁사 담당 AI*: "경쟁사는 카드뉴스로 이만큼 더 먹혔다"
  - *디자인 담당 AI*: "썸네일 색을 밝게 한 게 클릭률을 올렸다"
  - *전략 담당 AI*: "그럼 다음 주는 짧은 영상 + 밝은 썸네일 비중을 늘리자"
- **결과**: 회의 결론이 **1번(소재)·2번(제작)으로 자동 전달** → 콘텐츠의 방향성과 디자인이 **스스로 디벨롭**된다.
- **사람 개입**: 없음 (자동). 단, 회의 결론 요약은 성적표에 같이 넣어 사람이 흐름을 볼 수 있게 한다.

> 🧠 비유: 매주 **마케팅 팀 회의**가 자동으로 열리는 셈. 사람 팀원 대신 전문 분야별 AI가 모여 "다음엔 이렇게 가자"를 정하고, 그 결정이 바로 공장에 반영된다.

## 3. 클라이언트 납품 구조 — "공장 한 대씩 복제" 🏭🏭🏭

여러 회사에 파는 게 목표이므로:

- **공장(벨트)은 똑같이 하나만 잘 만들어 둔다.**
- 클라이언트마다 **"설정표 한 장"** 만 갈아 끼우면 그 회사 전용 라인이 가동된다.
- 각 클라이언트 정보는 **각자 잠긴 서랍**에 따로 보관 → A사·B사 내용이 절대 섞이지 않음.
- **새 클라이언트 받기 = 설정표 작성 → 라인 가동.** (이게 납품 속도의 핵심)

### 클라이언트 설정표(한 장) 예시
```
회사 이름      : OO카페
업종/주제      : 디저트, 신메뉴, 지역 맛집
벤치마킹 대상  : 경쟁 카페 인스타 3곳 + 잘나가는 디저트 계정 2곳 ← 자동 모니터링
브랜드 말투    : 친근하고 따뜻하게, 이모지 적당히
금지어         : (경쟁사명), 과장 표현
올릴 SNS       : 인스타그램, 네이버 블로그, 스레드
발송 시간      : 매일 오전 11시, 오후 7시
검수 스위치    : 처음엔 [켬] → 한 달 뒤 [끔]
계정 출입증    : (각 SNS 연결 열쇠) ← 잠긴 서랍에 보관
성적표 받을 곳 : 사장님 카톡 / 이메일
```
> 새 클라이언트는 **이 표만 채우면 끝.** 공장 내부는 손대지 않는다.

## 4. 95% → 100% 자동으로 가는 길 🔁

| 단계 | 사람이 하는 일 | 자동화율 |
|------|----------------|----------|
| 도입 초기 | 게시 전 OK 누르기 + 클라이언트 설정 | 약 90% |
| 안정기 | 가끔 성적표 보고 방향만 조정 | 약 95% |
| 완전 자동 | **검수 스위치 끔** → 사실상 안 봄 | 99%+ |

핵심은 **검수 스위치 하나로 사람의 개입을 0에 수렴**시키는 것.
처음부터 100%로 켜지 말고, **신뢰가 쌓이는 만큼 클라이언트별로 끈다.**

## 5. 진짜 자동을 굴리는 3대 필수 장치 ⚙️

지금까지 만든 건 "리허설"이고, 무인 운영을 하려면 이 3개가 더 필요하다.

1. **24시간 안 꺼지는 관리인 (상주 직원)**
   지금은 "실행!" 명령해야 한 번 돈다. 진짜 자동은 **아무도 없어도 새벽에 알아서 게시**돼야 하므로, 늘 대기하는 관리인이 필요.

2. **고장 알림벨 (경비 시스템)**
   계정 연결이 끊기거나 오류가 나면 **즉시 알림.** 안 그러면 며칠째 안 올라가는 걸 모를 수 있다.

3. **관제실 상황판 (한눈에 보는 화면)**
   어떤 클라이언트 글이 올라갔고, 뭐가 대기 중이고, 성적이 어떤지 **한 화면에서** 보고, **클라이언트에게도** 보여주면 신뢰 상승.

## 6. 구축 순서(로드맵) — 무리하지 않게 4단계로

> 큰 공장을 한 번에 짓지 않고, 매 단계마다 **돌아가는 결과물**을 본다.

- **1단계 — 자동 골대 세우기**
  "항상 켜진 관리인" + "클라이언트별 잠긴 서랍" 구조. → 무인으로 예약·발송이 도는 뼈대.
- **2단계 — 제작 공장 진짜로 가동 (+ 시장 조사)**
  AI로 글·이미지·썸네일을 실제로 생성해 붙인다. 경쟁사·트렌드 자동 모니터링과 제작 도구 자가 업그레이드를 함께 얹는다.
- **3단계 — 성적표 + 학습실(AI 회의실)**
  성적 자동 수집·발송(경쟁사 비교 포함), AI들끼리 회의해 방향성·디자인을 다음 콘텐츠에 반영.
- **4단계 — 관제실 + 검수 스위치**
  상황판 화면과 클라이언트별 검수 켬/끔 → 납품·운영 완성, 100% 자동 전환.

## 7. 지금 상태 vs 목표

> 표기: ✅ 뼈대 완성(mock 동작) · 🔌 실제 API 연결만 남음 · ⏳ 아직 미착수

| 작업소 | 지금 | 남은 일 |
|--------|------|---------|
| 소재 수집 | ✅ 시장조사·경쟁사 모니터링·반응 강화 **구조 완성**(`MarketResearch`) | 🔌 실제 검색/모니터링 데이터 소스 연결 |
| 콘텐츠 제작 | ✅ Claude 글 + **Gemini 나노바나나 이미지** + **디자인 자가 진화**(`DesignStudio`: 반응도로 스타일 업그레이드) | 🔌 ANTHROPIC/GEMINI/IMGBB 키 입력 |
| 검수 | ✅ 켬/끔 스위치 완성(`ReviewGate`: manual→rules→auto) | — (운영하며 단계 전환) |
| 발송 | ✅ 멀티채널 동시 발행 | 🔌 각 SNS 실제 API + ⏳ 24시간 무인 가동 |
| 성적표 | ✅ 집계 + 경쟁사 비교 구조 | 🔌 자동 발송(메일/메신저) 연결 |
| 학습 | ✅ **AI 회의실 완성**(`Council`: 분야별 어드바이저 토론→방향) | 🔌 실제 LLM 토론으로 고도화(선택) |
| 클라이언트 복제 | ✅ 설정표 1장(`ClientConfig`) + 격리 저장소(`ClientStore`) | — |
| 둥근 벨트 | ✅ 한 사이클 자동 완주 + 강화 환류(`Orchestrator`) | — |
| 관리인(데몬) | ✅ scheduleTimes 자동 트리거(`AutomationDaemon`) + **Docker 배포 준비** | 🏗️ 호스팅 위치 결정(회원님) |
| 알림벨 | ✅ 알림 허브(`AlertHub`) | 🔌 Slack/이메일 싱크 연결 |
| 상황판 | ✅ **관제실 상황판 완성**(`StatusBoard`, `board` 명령) | ⏳ 웹 화면(선택) |
